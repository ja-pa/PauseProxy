PAUSEPROXY / SETUP

Your first break

Start with the demo, then connect your browser. Settings default to HTTP on your trusted LAN and use your password. Opening settings does not require importing the CA; the CA is for proxied HTTPS sites.

1. Start the application

In config.dev.json, set a nonempty admin_password of your choice. There is no default password. Keep the configuration private. The password is never printed to the terminal.

"admin_addr": "127.0.0.1:9083",
"admin_url": "http://127.0.0.1:9083",
"admin_password": "YOUR_OWN_PASSWORD"

This is a configuration excerpt. Stop any existing Windows or WSL instance first; only one instance should use the configured ports and rules file.

In Ubuntu WSL, open the project directory (a Windows C: path is under /mnt/c/) and run:

bash ./run_test.sh
# Checks only, without starting the server or creating a CA:
bash ./run_test.sh --check
# Explicitly skip the race detector:
bash ./run_test.sh --skip-race

The script builds and tests the app, downloads the local Go toolchain if needed, and creates a CA only if its directory is missing. It reuses an existing CA. Keep the terminal open. If GCC is missing, install build-essential in Ubuntu. For native Windows, use ./scripts/dev.ps1 start -Config config.dev.json.

2. Trust the public CA

For proxied HTTPS sites (and settings only when configured with HTTPS), download the public certificate from http://127.0.0.1:9082/ca-cert.pem, or copy ca-cert.pem from the configured CA directory. The download endpoint does not require settings login.

Download public CA certificate

Save it in Downloads as pauseproxy-ca.pem. In Windows PowerShell, run:

certutil -user -addstore Root "$env:USERPROFILE\Downloads\pauseproxy-ca.pem"

Alternatively, import the public certificate with certmgr.msc under Trusted Root Certification Authorities. Restart the browser and open the exact admin_url from your configuration. HTTP settings do not require a certificate. This CA is needed for proxied HTTPS sites and optional HTTPS settings. Never import or share ca-key.pem. If the CA is recreated, import the new public certificate on every device.

3. Try the demo

Open demo ↗ · Open settings

  1. Sign in using your configured password. Reloading settings requires signing in again.
  2. Select a site in the demo and click the test button. Overview updates approximately every two seconds; the demo sends a heartbeat approximately every five seconds.
  3. Open two demo tabs: time must not count twice. Hide both tabs or leave the focused tab idle for one minute to pause tracking.
  4. In Sites & limits, lower the budget below the time already used. The demo shows “Time for a break”. Increase the limit to restore access at the next heartbeat.

The initial budget is two minutes, with a warning at 30 seconds. The demo spends the selected site's real budget. Reset statistics before testing a real site if needed. Rules survive reset and restart; statistics are only in memory.

PAC is a system setting and can affect other browsers. Only exact enabled target domains are proxied; media exceptions go directly. Turn PAC off before stopping the server or tracked sites may stop loading.

How tracking works

Time counts only when the page is visible, focused and has received interaction in the last 60 seconds. Mouse movement, clicks, keys, touch and scrolling renew activity; video playback alone does not. If the final inactive message is lost, the server can count up to the remaining ten seconds of the last heartbeat lease.

The timer displays minutes and seconds, or hours for longer budgets, and refreshes with server replies. The small gear opens Sites & limits in a new tab. The time itself is not a link. WebSocket and SSE remain unsupported in this MVP.

Sites, limits and media exceptions

Use an X or YouTube preset, or enter a custom main domain and exact target domains. Extra subdomains are not included automatically. New sites start with 15 minutes. Presets are suggestions until you save. Each user has separate budgets. A site can have its own budget or share time with a group.

In Sites & limits, use + Add group to create a shared daily budget. Assign sites using Shared group budget, Group budget + site limit, or Independent budget. Independent sites do not spend group time. A site cap and the group limit both apply; extra time can extend only the site cap. Grayscale follows the site's own usage. Different sites used simultaneously each spend group time; multiple tabs of one site count once. Changes apply from saving, without moving earlier group usage. Overview groups sites under a shared progress bar.

Media exceptions include all subdomains. X uses twimg.com; YouTube uses googlevideo.com and ytimg.com. A target domain cannot also be an exception. Media on the same domain as a tracked page cannot be separated this way; direct media URLs can remain available while the site is blocked.

After changing domains, refresh PAC: on Windows switch the setup script off and on; on Android set Wi-Fi proxy to None, save, then restore Proxy Auto-Config. Close affected tabs. After changing media exceptions, restart the browser to close old connections.

Limits apply at the next heartbeat. Disabling or deleting a rule removes tracking and the overlay. Rules are stored in sites_file; manual file edits require a restart. Invalid files are not overwritten, and failed saves preserve existing rules and PAC. Tab switching keeps unsaved form edits.

Android Chrome over Wi-Fi

Addresses and configuration

Connect the phone and PC to the same trusted network. Find the PC's active LAN IPv4 address with ipconfig, and the phone's address in Wi-Fi details. The following example uses PC 192.168.1.50 and phone 192.168.1.60; replace both with your addresses. A router address reservation helps keep them stable.

Copy your configuration to config.android.json and adjust these fields, preserving the CA and rules paths:

"proxy_addr": "0.0.0.0:9080",
"pac_addr": "0.0.0.0:9082",
"admin_addr": "0.0.0.0:9083",
"admin_url": "http://192.168.1.50:9083",
"admin_password": "YOUR_OWN_PASSWORD",
"advertised_proxy": "192.168.1.50:9080",
"users": {
  "127.0.0.1": "dev",
  "::1": "dev",
  "192.168.1.50": "dev",
  "192.168.1.60": "android"
}

This is an excerpt, not a full JSON document. Both PC and phone open settings at the exact admin_url. Never enter 0.0.0.0 into the browser: it is only a listening address. The phone must be in users to access the proxy or PAC. Settings login is available before registration and requires the admin password. To register a device, add its IP to users in the JSON configuration and restart PauseProxy; the admin UI does not yet edit device registrations.

Network and startup

For WSL, configure mirrored networking in your existing %USERPROFILE%\.wslconfig under [wsl2]: networkingMode=mirrored. Save other WSL work before running wsl --shutdown, then reopen Ubuntu. If mirrored networking is unavailable, run the native Windows app.

On a Private Windows network, add firewall rules in an administrator PowerShell, limited to the phone's address. Replace the example addresses; update existing rules rather than duplicating them:

New-NetFirewallRule -Name PauseProxy-Android -DisplayName "PauseProxy Android" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 9080,9082,9083 -LocalAddress 192.168.1.50 -RemoteAddress 192.168.1.60 -Profile Private
# Only for WSL mirrored networking:
New-NetFirewallHyperVRule -Name PauseProxy-Android-WSL -DisplayName "PauseProxy Android WSL" -Direction Inbound -Action Allow -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol TCP -LocalPorts 9080,9082,9083 -RemoteAddresses 192.168.1.60

Stop the previous instance. On Windows use ./scripts/dev.ps1 start -Config config.android.json. In WSL:

bash ./run_test.sh --check
.tools/go-linux/go/bin/go build -o dist/pauseproxy-linux ./cmd/pauseproxy
./dist/pauseproxy-linux --config config.android.json

Use go instead if the runner used a system toolchain. The existing CA must already be present. The runner without --check starts config.dev.json, not the Android configuration.

Certificate, settings and PAC

  1. Before enabling proxy, open http://192.168.1.50:9082/healthz and the demo on the phone.
  2. Download http://192.168.1.50:9082/ca-cert.pem. Rename the downloaded copy to pauseproxy-ca.crt if the certificate picker requires it.
  3. In Android settings, find Install certificate → CA certificate (usually under Security → Encryption & credentials). Install the public PauseProxy Development CA, not a Wi-Fi or VPN client certificate. Menu names vary by device. Restart Chrome.
  4. Open http://192.168.1.50:9083 and sign in. The timer gear opens the same address.
  5. Edit the connected Wi-Fi network → Advanced → Proxy → Proxy Auto-Config. Enter http://192.168.1.50:9082/proxy.pac. The PAC must advertise the PC's LAN address, not loopback.
  6. If only manual proxy is available, use host 192.168.1.50 and port 9080. This routes all supported browser traffic through the proxy; only enabled target domains are decrypted. PAC is preferable for selective routing.

Test X in Chrome, not the native app. Verify the android user in Overview, pausing in the background, blocking and restored access after raising the limit. This setup is for Wi-Fi, not mobile data; managed devices may prohibit user CA installation.

Troubleshooting

Port already in use

Stop your previous instance in its terminal. Inspect with Get-NetTCPConnection -State Listen -LocalPort 9080,9082,9083 on Windows or ss -ltnp in WSL. Do not stop unrelated processes.

Certificate error or settings will not open

Use the exact configured admin_url, including its HTTP or HTTPS scheme. Only for HTTPS, import the public certificate of the currently running CA. Download it through port 9082 before opening settings. Do not bypass certificate checks. A different IP or “localhost” hostname will not match the configured address. If the PC's IP changes, update the configuration and restart.

403 / unknown device / host-or-origin denied

For proxy or PAC access, check the device's current IP against users. Unregistered devices opening the PAC server root or demo are redirected to settings. Settings accepts unregistered devices, requires the admin password, and the browser address must match admin_url exactly. For phone connectivity, check all three ports, firewall rules, mirrored networking and guest Wi-Fi client isolation.

Timer missing or a partially loaded blocked page

Try the demo, then inspect Overview → Technical diagnostics. Injections without sessions suggest a client startup problem; sessions without heartbeats suggest communication failure. Try Ctrl+Shift+R or a fresh browser profile. In DevTools → Application → Service Workers, unregister an old worker and close other tabs for the site. The injected client also unregisters existing workers once; cached pages without the client cannot do this. Unregistering does not clear cookies. Offline means the client has not received a status reply for ten seconds.

CA or rules file invalid

The app preserves existing files. Check the configured paths and permissions. Back up a CA before deliberately recreating it, then import the new public certificate on each device. Restarting clears in-memory statistics; saved rules remain.

After testing

  1. Restore the original proxy settings on Windows and Android before stopping the server.
  2. Stop your instance with Ctrl+C.
  3. If no longer needed, remove only PauseProxy Development CA from each device's user-trusted certificates.
  4. Remove firewall rules you created:
Remove-NetFirewallRule -Name PauseProxy-Android
# Only if created:
Remove-NetFirewallHyperVRule -Name PauseProxy-Android-WSL

The application does not change system proxy or certificate trust automatically.
